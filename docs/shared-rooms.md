# 共享房间与运行说明

## 本机启动

Node.js 22+，无需安装依赖：`npm run serve`。默认监听 `127.0.0.1:4173`，房间存入项目 `data/`，只对当前电脑开放。公网地址尚未选择。

PowerShell 可指定端口和另一个持久化目录：

```powershell
$env:PORT='4173'
$env:DATA_DIR='D:\AI\expedition-journal\data'
npm run serve
```

之后选好托管环境，再配置同源 HTTPS 服务；不要把 127.0.0.1 邀请链接当成玩家可访问的公网地址。服务进程需要长期运行，`DATA_DIR` 必须放在持久卷，不能只放临时部署目录。`HOST` 默认回环地址；反向代理或容器运行时可按环境显式配置。

`dist/` 可静态保存私有手记；共享需要同时提供 `/api/`。反向代理须关闭 `/events` 的缓冲，并允许长连接。服务已有心跳、`X-Accel-Buffering: no` 和重连。备份整个 `DATA_DIR` 时建议先停止进程，保持 room.json 与图片一致；不要将该目录提交到 Git。

## 团内使用

1. 登记/选择角色，选好要共享的远征。
2. 展开上方远征名册，在该远征下面点“建立共享版本”；原私有手记保留。同一远征的两个版本分别保存，收在同一个子项内。
3. 点击共享子项旁的“邀请同伴”，复制完整链接。链接持有者是共同编辑者。
4. 同伴打开链接，选自己的角色。笔迹、附图、回复和物品都属于同一房间。
5. 共享版完整备份可恢复为私有副本。恢复不会向服务器房间回写。
6. 枭熊房间可以安装 `/manifest.json`，由主持人绑定这个共享邀请。房间同伴得到同一共享远征的入口；网站与扩展使用同一服务地址。详见 [Owlbear 扩展](owlbear.md)。

## 持久化与同步

- `POST /api/rooms` 建房；邀请含随机房间 ID 和 256 位随机凭据。邀请凭据在 URL fragment，API 使用 Bearer header，磁盘仅保存凭据哈希；第三方请求不能读取房间数据。
- `GET /api/rooms/:id` 读取快照，`POST /changes` 保存变更，`GET /events` 同步快照，`PUT/GET /assets/:id` 上传/读取房间图片。所有房间接口要求凭据。
- 每房间的修改在服务器串行处理，写临时文件后替换 room.json。新手记篇次由服务器分配；客户端重试同一保存编号不会重复交付。
- 服务合并“上次版本 → 我的修改 → 房间现状”。不同条目/字段可同时写；相同字段冲突返回差异，不能静默覆盖。打开表单时保留原版本，提交前也与当前房间比较；正文、物品说明和图片数组不会因后台更新后提交旧表单而被悄悄覆盖。库存数量同时减少，即使结果数值相同，也会判为冲突，防止重复领取。
- 浏览器的待发送队列先落到本机存储，再发送；确认丢失时用服务器保存编号回执消除重复操作。连接中断后重试，已加入的房间支持文字继续书写。上传图片需要在线。
- SSE 写入缓冲繁忙时保留一份最新快照，排空后再发，避免较大头像导致断开，也避免对慢连接不断堆积历史快照。
- 冲突时保留自己的内容，先导出副本，再选择房间版本；原待发送队列另留本机恢复副本。共享撤销采用反向字段合并，避免撤掉同伴的无关新增内容。

## 运行边界

这是邀请制的团内共同编辑服务，没有独立登录、角色所有权验证或管理员撤权。不要把邀请放入公开网页。公网运营前应按实际用户规模补充邀请轮换、账户/权限、建房限制和运行监控。

房间上限默认 100；图片上限每房间 160 MB，单图 12 MB。旧上传仍占上限；暂未做图片垃圾回收或大备份拆分。数据 JSON 请求上限 16 MB，完整备份导入上限 100 MB。多人合并并不保证把同一篇正文的同时改写逐字合并；冲突会暂停并提示保留副本。

当前源码和本机测试不包含公网部署。Owlbear 已提供房间绑定入口，场景地图事件互通仍是后续工作。安装清单和图标允许公开跨域读取；共享 API 不开放通配 CORS，仍要求房间邀请凭据。
