# 已确认需求

## 用户与战役

- 产品服务多个西征团，不绑定单一团名。
- 主持人可创建独立战役页面。战役之间的角色、地图、日记和物品隔离。
- 玩家使用简单的角色登记板，自己输入角色姓名，并可增加新角色。
- 同一玩家可拥有多个角色；角色归属于具体战役。
- 角色姓名是显示信息，不能作为登录凭据或唯一身份标识。底层成员识别与权限机制仍需实施设计，界面保持低门槛。

## 日记与地图

- 自由日记正文是主要输入。不强制标题、分类、人物或线索表单。
- 自动保留实际作者与创建时间；角色署名与实际作者分别记录。
- 冒险日期与现实创建时间分别保存。冒险日期可沿用主持人设置的当前日期，补写时可修改。
- 排序方式：冒险时间、实际写入顺序。编辑旧日记不改变原始写入顺序；更新时间单独记录。
- 冒险日期未填写时明确标示，不能用现实日期冒充。自定义历法的输入和排序方案尚待确定。
- 用户可导入地图并放置标注；点击标注阅读关联日记。
- 同一地点可以关联多篇日记，支持作者筛选和上述两种排序。
- 地图与日记列表引用同一篇日记，修改后同步。地点关联可选。
- 编辑自动保存，提供明确的保存、未同步和失败状态。

## 背包与公库

- 每个角色有自己的背包；每个战役有共享公库。
- 玩家创建文本物品条目，基本内容为名称、数量和描述。
- 支持把背包里的物品存入公库，供其他玩家使用；转移必须同时更新来源与目标，防止重复。
- 物品查看权限与保管归属是不同概念。
- 复杂装备格、自动负重和规则系统不是首版重点。

## 设备与视觉

- 主要设备：桌面电脑、iPad、华为平板。
- 横屏优先；竖屏与分屏保持可读可写，不把跨页机械缩小。
- 不依赖悬停；拖动操作有可点按的替代，地图浏览不误触标记移动。
- 屏幕键盘出现时保留正文可见，支持实体键盘操作。
- 美术主参考为 14—16 世纪彩饰手抄本与时祷书，允许成熟、鲜明、华丽的彩饰。
- 日记为手抄本页面；公库与背包采用相协调的中世纪柜箱、布袋或牛皮包视觉。
- 优先采用明确开放使用的真实馆藏素材，保留来源；正文阅读与书写质量优先。

## 接入与数据

- 计划支持独立网站与 Owlbear Rodeo 扩展，两入口共用数据。
- 长期战役数据不能随当前战斗场景切换而丢失。
- 提供文档导出，以及含地图、标注、角色、物品与关联关系的可恢复备份。
- 旧腾讯文档的导入方式要依据实际样本验证，不预先承诺复杂格式无损导入。
- 公开仓库仅存项目源码、文档和可分发素材，不存真实战役内容或访问凭据。

## 尚待验证，不能当作已完成

- 邀请加入、记住设备、跨设备恢复身份和主持人权限。
- 冒险历法及同一天内事件的排序。
- 多人同时编辑、物品同时领取的冲突处理与恢复。
- 文档输出格式和原文档迁移保真程度。
- iPad / 华为平板实机兼容，以及 Owlbear 内嵌页面的会话行为。
